# 작업: 공고분석 미지원 사유 칸 (GitHub 이슈 #3)

## 목표
공고를 분석했지만 지원하지 않기로 했을 때, 그 이유를 공고분석에 글로 남겨 둘 수 있다.

## 동작
- 공고분석에 "미지원 사유" 칸(자유 글, 여러 줄)이 생긴다.
- 상태가 "지원 안 함"(`skipped`)일 때만 칸을 보여준다: 수정 화면에서는 입력칸으로, 상세 화면에서는 읽는 글로 보여준다. 이미 쓴 글이 있는데 상태를 바꿔서 칸이 사라지면 글은 지우지 않고 저장된 채로 둔다(다시 "지원 안 함"으로 바꾸면 다시 보인다). 입력칸 라벨은 "미지원 사유", 안내 글(placeholder)은 "지원하지 않기로 한 이유를 적어 두세요".
- 상세에서 상태가 "지원 안 함"이고 사유가 비어 있으면 "적어 둔 사유가 없습니다"처럼 빈 상태 문구를 보여준다(기존 상세의 빈 칸 문구 스타일을 따른다).
- 위치는 기존 화면의 결론(conclusion) 근처에 둔다. 정확한 자리는 기존 `JobEditScreen`/`JobViewScreen`의 구조를 보고 어울리게 정한다.
- 이미 있는 분석은 사유가 빈 글("")이 된다. 아주 긴 글도 `Text`라 그대로 저장한다.

## 데이터와 API
- `app/db.py`의 `JobAnalysisRow`에 `skip_reason: Text, default="", server_default=""` 추가, Alembic 마이그레이션(autogenerate 후 읽고 고침, DB 중립 기본값). `saveme_dev`에 먼저 적용.
- `app/models.py`에 `skipReason`(camelCase)을 공고분석 읽기·쓰기 모델에 추가, store와 라우터가 저장·반환.
- 프런트엔드 `types.ts`, `httpService.ts`, `mockService.ts`(같은 동작)에 같이 반영.
- 가져오기는 바꾸지 않는다: `docs/job-inbox.md`, `app/importers/jobs.py`에 이 칸을 넣지 않는다. 단, 가져오기·`--replace`가 이미 앱에서 적은 `skipReason`을 지우지 않는지 확인하고, 지운다면 보존하게 한다.

## 끝났다고 보는 조건
- 백엔드: 만들기·고치기·읽기에서 `skipReason`이 왕복하는 통합 테스트, 기본값 "" 테스트, 남의 데이터는 404 테스트(기존 것 유지), 마이그레이션이 PostgreSQL에서 적용됨. 가져오기 `--replace` 후에도 사유가 남는 테스트.
- 프런트엔드: 상태가 "지원 안 함"일 때만 칸이 보이고 다른 상태에서는 안 보이는 컴포넌트 테스트, 저장 값이 서비스에 전달되는 테스트, mock 동작 테스트. 입력칸은 16px 이상 규칙을 지킨다.
- 건드린 영역의 테스트, 프런트엔드 빌드, 린트 통과.

## 화면
- 목업에는 없는 칸이다. 기존 공고 수정·상세 화면(`JobEditScreen.tsx`, `JobViewScreen.tsx`)의 스타일과 칸 모양을 그대로 따른다. 모바일은 신경 쓰지 않는다.

## 하지 않을 것
- 고르는 목록(연봉·위치 등), 가져오기 형식 변경, 새 의존성, 모바일 작업.

## 사용자와 정한 것
- 자유 글만 받는다.
- 상태가 "지원 안 함"일 때만 보여준다.
- 가져오기에는 넣지 않는다 (앱에서만 입력).
- 버전은 PATCH.
