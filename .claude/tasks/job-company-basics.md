# 작업: job-company-basics (공고분석 상세의 [회사 기본] 탭)

## 목표
공고분석 상세에 [회사 기본] 탭을 더해, 사용자가 그 회사에 대해 직접 조사한 글과 궁금한 점(질문과 답)을 탭 안에서 바로 적고 고칠 수 있게 한다.

## 동작
- 공고분석 상세(`JobViewScreen`)의 탭이 [공고 분석] [회사 기본] [회사 동향] 순서가 된다. 주소의 탭 값은 `tab=basics` (기존 `tab=trends`, 없으면 공고 분석은 그대로). 주소에 남고 새로 고쳐도 그 탭이 열린다 (회사 동향과 같은 방식, `router.tsx`의 search 검사에 `basics`를 더한다).
- 회사 기본은 **공고분석 한 건마다** 따로 저장된다 (회사 동향과 같다). 같은 회사의 다른 분석과 공유하지 않는다.

### 보기 상태
- 아무것도 적지 않았으면 (조사 글이 공백뿐이고 Q&A가 0개) 카드 하나에:
  `아직 회사 기본을 적지 않았어요.` 줄바꿈 `회사에 대해 조사한 내용과 궁금한 점을 적어 두세요.` 그리고 버튼 `적기`.
- 적은 것이 있으면 탭 맨 위 오른쪽에 버튼 `편집`, 그 아래 카드 두 개 (빈 카드는 숨긴다):
  - `조사한 내용` 카드: 적은 글을 줄바꿈 그대로 (`white-space: pre-wrap`). 마크다운 해석 없음.
  - `궁금한 점` 카드: 머리 오른쪽에 `답 n / 전체 m` (답이 공백 아닌 것의 수). Q&A를 적은 순서대로, 면접후기 보기의 질문 모양(`ReviewViewScreen`의 `qlist`·`qv-h`·`qv-q` 스타일을 다시 쓴다)으로 번호 `Q1`, `Q2`…와 질문, 그 아래 답(줄바꿈 그대로). 답이 비어 있으면 답 자리에 흐린 글씨(`hint`)로 `아직 답을 못 찾았어요`.
- 이 탭에는 섹션 칩, 확인됨 바 변경, 근거 경험 태그가 없다. 머리(회사·직무, 메타 카드, 미확인 바)는 다른 탭과 같이 그대로 보인다.

### 편집 상태 (탭 안에서)
- [적기]나 [편집]을 누르면 같은 자리가 편집 폼으로 바뀐다:
  - `조사한 내용` 여러 줄 입력칸 (textarea, 내용에 따라 늘어나거나 충분히 큼, 16px 이상). 도움말: `회사 구조, 사업, 역사처럼 조사한 것을 자유롭게 적어요.`
  - `궁금한 점` 목록: 한 줄마다 `질문` 한 줄 입력칸, `답` 여러 줄 입력칸(placeholder `아직 모르면 비워 두세요`), 그 줄의 `삭제` 버튼(글자 버튼 또는 아이콘 버튼, aria-label `질문 n 삭제`). 목록 아래 `+ 질문 추가` 버튼 (빈 줄을 맨 아래에 더하고 그 질문 칸에 포커스).
  - 아래에 `취소`, `저장` 버튼.
- 저장 규칙:
  - 질문과 답이 둘 다 공백인 줄은 버리고 저장한다.
  - 질문이 공백인데 답이 있는 줄이 있으면 저장하지 않고 그 질문 칸 아래에 `질문을 적어 주세요`를 보이고 그 칸에 포커스.
  - 앞뒤 공백은 질문만 다듬는다 (답과 조사 글은 적은 그대로, 단 전체가 공백이면 빈 글로).
  - 성공하면 보기 상태로 돌아가고 토스트 `회사 기본을 저장했어요`. 실패하면 편집 상태를 그대로 두고 토스트 `저장하지 못했어요. 다시 시도해 주세요.` (세션 오류는 다른 화면처럼 `useSessionErrors`).
  - 저장 중에는 [저장] 버튼을 막는다.
  - 저장해도 분석의 사람 확인(Y/N)은 바뀌지 않는다.
- [취소]는 바꾼 것을 버리고 보기 상태로 (확인 창 없음). 편집 중 다른 탭으로 가도 바꾼 것은 버려진다 (확인 창 없음).
- 순서 바꾸기는 없다 (적은 순서, 새 질문은 맨 아래).

## 데이터와 API
- `jobs` 테이블에 칸 두 개 (마이그레이션 하나, `user_id`는 이미 있음):
  - `company_note`: `Text`, 기본 `""` (`server_default=""`).
  - `company_qna`: `JSON`, 기본 `[]` (`server_default="[]"`), 원소는 `{"question": str, "answer": str}`. 기존 행은 빈 값이 된다.
- API 모델(`app/models.py`, camelCase): `Job`에 `companyNote: str`, `companyQna: list[CompanyQna]` (`CompanyQna = {question, answer}`). `JobInput`(편집 화면 저장)에는 넣지 않는다.
- 새 엔드포인트 `PUT /api/jobs/{id}/company-basics`, 몸통 `{companyNote, companyQna}`, 답은 저장된 `Job` 전체. `current_user`, `require_csrf_header`. 남의 분석이나 없는 id는 404. 질문이 공백인 원소가 오면(답이 있든 없든) 서버는 둘 다 공백이면 버리고, 답만 있으면 422. store 메서드는 `user_id`를 받는다 (예: `stores.jobs.set_company_basics(user_id, job_id, data)`).
- 기존 동작이 회사 기본을 지우지 않게:
  - 분석 [편집] 화면의 저장(`update`)은 `company_note`·`company_qna`를 건드리지 않는다.
  - 가져오기 `--replace`/`--replace-verified`(`save_imported`)도 두 칸을 그대로 둔다 (지원 건 연결처럼). 새로 만드는 분석은 빈 값.
- 프런트엔드 서비스: `types.ts`의 `Job`에 `companyNote`, `companyQna`, `SaveMeService`에 `setJobCompanyBasics(id, input): Promise<Job>`. `httpService.ts`와 `mockService.ts`(같은 다듬기·버리기·오류 규칙, 없는 id는 다른 mock 메서드처럼 not found)를 맞춘다. `sampleJobs.ts`의 샘플 하나에 지어낸 회사 기본(조사 글과 Q&A 2~3개, 그중 하나는 답 없음)을 넣는다. 사용자의 진짜 내용은 넣지 않는다.
- 에이전트 조회 `app.agent_read`의 `job ID` 출력에 `## 회사 기본` 절을 더한다: 조사 글, 그다음 `궁금한 점`을 `Q. 질문` / `A. 답`(답 없으면 `A. (아직 답 없음)`)으로. 둘 다 비면 절을 빼거나 `(없음)`으로 (다른 절의 방식을 따른다). `--reader`(면접관 시점)에는 넣지 않는다.

## 끝났다고 보는 조건
- 탭 세 개가 정해진 순서로 보이고, `tab=basics`가 주소에 남고 다시 열어도 그 탭이다 (`router.test.tsx`).
- 컴포넌트 테스트: 빈 상태 글과 [적기], 적고 저장하면 보기 상태에 조사 글·Q 번호·답·`아직 답을 못 찾았어요`·`답 n / 전체 m`가 보임, 빈 줄은 버려짐, 질문 없이 답만 있으면 `질문을 적어 주세요`로 막힘, [취소]가 버림, 저장 실패 토스트.
- mock 서비스 테스트: 다듬기·버리기 규칙, 분석 편집 저장이 회사 기본을 지우지 않음.
- 백엔드 통합 테스트: PUT 저장과 GET 반영, 남의 분석은 404, 없는 id 404, 답만 있는 원소 422, CSRF 헤더 없으면 403, `PUT /api/jobs/{id}`(편집 저장) 뒤에도 회사 기본이 남음, 저장해도 `verified`가 그대로.
- 가져오기 테스트: `--replace`로 바꿔도 회사 기본이 남음.
- `agent_read` 테스트: `job ID` 출력에 회사 기본이 있고 `--reader`에는 없음.
- 마이그레이션이 PostgreSQL에서 `tests/unit/test_migrations.py`를 통과하고 `saveme_dev`에 적용됨.
- 프런트엔드 빌드·린트 통과.

## 화면
- 목업에 없는 새 탭이다. 탭 줄과 머리는 기존 `JobViewScreen`의 `jtabs`, 빈 상태 카드는 `JobTrendsTab`의 `tr-empty`, Q&A 보기 모양은 `ReviewViewScreen`의 질문 목록, 편집 폼의 칸은 다른 편집 화면의 `Field`와 입력 스타일을 다시 쓴다. 새 CSS는 `styles.css`에 조금만, 고정 px 폭 없이.

## 하지 않을 것
- 회사 이름이 같은 분석끼리 회사 기본을 공유하지 않는다.
- 분석 [편집] 화면에 회사 기본 섹션을 만들지 않는다.
- 공고분석 받은편지함 양식(`docs/job-inbox.md`)과 가져오기 JSON에 회사 기본을 넣지 않는다.
- Q&A 순서 바꾸기, 즐겨찾기, 말풍선 여러 개, 출처 칸은 만들지 않는다.
- 모바일 레이아웃은 만들지 않는다.

## 사용자와 정한 것
- 회사 기본은 공고분석 한 건마다 저장 (회사 동향처럼).
- [회사 기본] 탭 안에서 바로 적고 고친다 (편집 화면 섹션이 아님).
- Q&A 한 개는 질문 + 답 하나. 답이 비면 "아직 답을 못 찾았어요".
- 탭 순서: 공고 분석 · 회사 기본 · 회사 동향.
- 에이전트 조회(`agent_read job ID`)에 넣고, 면접관 시점(`--reader`)에는 넣지 않는다.
- 공고분석을 다시 가져와 바꿔도(`--replace`) 회사 기본은 그대로 남는다.
