# 작업: agent-read (에이전트용 조회 명령과 권한)

## 목표
Claude 에이전트(공고분석·서류 작성·검증·검토)가 DB에 직접 접속하지 않고도 사용자의 경험·프로필·인성답변·면접후기·기존 공고분석을 **조회**할 수 있게 한다. 조회 전용 명령을 만들고, 에이전트가 DB를 직접 건드리지 못하도록 권한을 설정한다. 에이전트 파일 4개(`job-analyst`, `doc-writer`, `risk-checker`, `doc-reviewer`)는 이 작업에 넣지 않는다 (이 작업이 병합된 뒤 별도 작업 `job-agents`에서 만든다).

## 용어 (섞어 쓰지 말 것)
- **조회**: DB에서 꺼내 보기만 한다. DB는 바뀌지 않는다.
- **저장**: DB에 넣는다. 반드시 기존 "가져오기" 명령(`app.importers.jobs`, `app.importers.documents`)으로만 한다.

## 배경
다른 프로젝트에서 쓰던 역할 에이전트 4개를 이 저장소로 옮기는 일의 1단계다. 옛 프로젝트는 경험·프로필을 마크다운 파일로 읽었는데, 이 데이터는 이미 PostgreSQL DB에 들어 있다. 에이전트는 DB에서 꺼내 보고(조회), 결과는 가져오기 명령으로 넣는다(저장).

## 동작

### 조회 명령
`uv run python -m app.agent_read <하위명령>` (`backend/` 안에서. 파일 이름·위치는 `backend/app/importers/` 같은 기존 관례를 보고 조정해도 된다). **조회 전용**: DB를 바꾸는 코드(insert/update/delete/commit)가 없어야 한다.

- 대상은 `stores.users.dev_user()`의 데이터뿐이다 (기존 가져오기와 같은 방식, 로그인 없는 로컬 단일 사용자). **user_id를 인자로 받지 않는다**: 에이전트가 사용자를 지정할 수 없어야 한다. 모든 읽기는 기존 store 메서드(`user_id`로 거름)를 거치고, store에 없는 읽기가 필요하면 읽기 전용 메서드를 store에 더한다. 라우터를 거치지 않고 SQL을 직접 쓰지 않는다.
- `DATABASE_URL`은 환경 변수에서 (기존 가져오기와 같다). 기본값 동작도 가져오기 명령을 따른다.
- 하위명령:
  - `experience-index`: 경험 목록(id, 제목, 기간 등 한눈에 보는 정보) + 쓰인 태그의 표준 어휘 + 행동질문 매핑(경험이 어떤 행동질문에 답하는지). 경험이 어떻게 구분·태그되는지는 `app/db.py`의 experiences 계열과 `app/stores/experiences.py`로 파악한다.
  - `experience <id>`: 한 건의 상황·과제·행동·결과, 프레이밍 주의, 담당 범위(본인이 한 일과 팀이 한 일의 구분), 연결(experience_links). 없는 id, 남의 id는 "없다"는 메시지와 0이 아닌 종료 코드.
  - `profile`: 기본 정보(resume_basics), 이력(careers), 스킬(skill_groups).
  - `personality`: 인성답변(personality_answers).
  - `reviews`: 면접후기(interview_reviews 계열).
  - `jobs`: 기존 공고분석 목록(회사, 직무, 분석일, 확인 여부, 지원 건 연결 여부). 에이전트가 같은 (회사, 직무)가 이미 있는지 알아보는 데 쓴다.
- 출력은 **마크다운**으로 한다 (에이전트가 읽기 좋고, 근거 표시 문구를 눈에 띄게 쓸 수 있다). JSON은 아니다. 이유를 보고서에 한두 줄 적는다. 사용자가 쓴 글은 그대로 옮기고 요약하거나 고치지 않는다. 글이 길어도 자르지 않는다.
- 하위명령 없음/모르는 하위명령은 사용법을 한국어로 보여주고 0이 아닌 종료 코드.

### 근거 구분 (이 작업의 핵심)
아래 둘은 이력서·자소서의 **근거가 아니다**. **기본 출력에 나오지 않는다.** `--include-reference` 옵션을 줄 때만 나오며, 그때도 그 블록 맨 앞에 `⚠ 근거 아님(면접 대비 참고용)` 문구를 붙이고 서류 근거로 쓰지 말라는 한 줄을 더한다.

1. 경험의 `예상 질문과 답변`(experience_qas): 면접 대비용으로 만든 답변 예시일 뿐 실제 수행이 검증되지 않았다. 기본에서 뺀다. `experience <id>`와 `experience-index` 어디에도 기본으로는 나오지 않는다 (개수도 보여주지 않는다. 있는지만 알리는 한 줄은 허용: "예상 질문과 답변은 `--include-reference`로 볼 수 있음").
2. 면접후기의 AI 첨언·미분류: AI가 쓴 글이거나 출처 불명이다. 후기에서 근거로 쓸 수 있는 것은 사용자가 쓴 `내 답`, `다시 답한다면`, `메모`뿐이다. 기본에서는 이 셋만 낸다. `다시 답한다면`에는 "실제로 한 답이 아님(다시 답한다면)" 표시를 붙인다. AI 첨언·미분류 질문/답은 `--include-reference`에서만, 근거 아님 표시와 함께 낸다. (후기에서 어느 칸이 어느 출처인지는 `app/db.py`·`app/models.py`·`app/stores/reviews.py`·`app/importers/reviews.py`로 파악한다. 출처 구분 칸이 모호하면 짐작하지 말고 보고서에 질문으로 남기고, 모호한 칸은 근거 쪽이 아닌 제외 쪽으로 처리한다.)

`--include-reference`는 `experience <id>`, `experience-index`, `reviews`에서 쓸 수 있다. 나머지 하위명령에서는 의미가 없으니 받지 않는다.

### 권한 설정
**`.claude/settings.json`** (저장소에 커밋되는 파일, 없으면 만든다. 이미 있으면 기존 내용 유지)에 반영한다. `.claude/settings.local.json`은 건드리지 않는다 (알림 훅이 들어 있고 개발자 worktree에 없다).

- 허용(`allow`): 조회 명령(`agent_read` 하위명령 전부), 가져오기 명령의 `--dry-run`.
- 확인 요구(`ask`): 가져오기 명령의 실제 저장(`--dry-run` 없는 `app.importers.jobs`, `app.importers.documents` 실행).
- 거부(`deny`): `psql`, `docker exec`, `docker compose exec`(DB 직접 접근).
- 규칙 문법은 Claude Code 문서의 `Bash(...)` 패턴을 확인해서 쓴다 (모르면 `claude-code-guide` 에이전트로 확인하거나 `update-config` 스킬 지침을 따른다). 가져오기 `--dry-run`과 실제 저장이 어느 쪽 규칙에 걸리는지(예: `deny` > `ask` > `allow` 우선순위, 인자 순서가 달라도 걸리는지, `uv run` 앞뒤 `cd`가 붙은 복합 명령은 어떻게 되는지)를 **실제로 시험해서** 확인하고, 시험 방법과 결과를 보고서에 적는다. 자동 승인이 안 되는 항목이 있으면 그것도 적는다. 시험은 진짜 DB `saveme`에 쓰지 않는 명령으로만 한다 (실제 저장 규칙은 `--dry-run`을 빼고 돌리면 쓰게 되므로, 그 줄은 명령을 실행하지 말고 규칙 판정만 확인한다: 예를 들어 `ask`에 걸리는 명령은 사용자 확인 창이 뜨는지만 보고 거절한다. 시험하기 어려우면 사용자에게 시험을 부탁하는 문구를 보고서에 남긴다).
- 에이전트 파일에서 `--replace-verified`를 쓰지 않는다는 규칙은 2단계(`job-agents`)에서 다룬다. 여기서는 `settings.json`에서 `--replace-verified`가 든 가져오기 명령을 `deny`에 넣어도 되는지 판단해 넣는다 (넣으면 사용자가 직접 터미널에서 돌려야 한다는 점을 보고서에 적는다).

## 데이터와 API
- 새 테이블·칸·마이그레이션·HTTP 엔드포인트 없음. 읽기 전용 명령과 (필요하면) store의 읽기 메서드만 더한다.

## 끝났다고 보는 조건
- `uv run python -m app.agent_read`의 모든 하위명령이 `saveme_dev` 또는 테스트 DB에서 동작한다.
- 테스트 (단위 + 통합, PostgreSQL. `docs/testing.md`의 방식으로 `TEST_DATABASE_URL`):
  - 근거 아닌 데이터(예상 질문과 답변, 후기의 AI 첨언·미분류)가 **기본 출력에 없다**. 문구를 심어 두고 출력에 그 문구가 없음을 확인한다.
  - `--include-reference`에서는 나오고 `⚠ 근거 아님(면접 대비 참고용)` 표시가 그 앞에 있다.
  - 후기의 `다시 답한다면`에 "실제로 한 답이 아님" 표시가 붙는다. `내 답`, `메모`는 표시 없이 나온다.
  - 다른 사용자의 데이터가 어느 하위명령에도 섞이지 않는다 (사용자 둘을 만들어 두고 `dev_user()`의 것만 나옴을 확인). 남의 경험 id로 `experience <id>`를 부르면 없는 것처럼 실패한다.
  - 조회가 DB를 바꾸지 않는다: 명령 전후로 관련 테이블 행 수가 같다.
  - `--user-id` 같은 사용자 지정 인자가 없다 (인자 파서 테스트).
- 건드린 영역의 테스트만 돌린다 (`AGENTS.md`의 규칙). 전체는 CI에서.
- 린트 통과. 모델·마이그레이션은 건드리지 않으므로 `test_migrations.py`는 필요 없다.
- 권한 설정을 어떻게 시험했는지 보고서에 있다.
- `AGENTS.md`의 "로컬 운영" 절 가져오기 설명 근처에 조회 명령 한 줄과 `.claude/settings.json`의 권한 한 줄을 더한다 (길게 쓰지 않는다). 에이전트 4개 안내는 `job-agents`에서 넣는다.

## 하지 않을 것
- 에이전트 파일 4개(`.claude/agents/*`) 만들기. 별도 작업이다.
- 진짜 DB `saveme`에 쓰기, `private/`의 진짜 데이터 읽기·커밋. 시험은 `saveme_dev`와 `TEST_DATABASE_URL`에서만.
- 조회 명령에 쓰기 기능, 사용자 지정 인자, 직접 SQL 실행 입력 만들기.
- 새 의존성 (필요해 보이면 멈추고 질문).
- 마이그레이션, 모델 변경, 프런트엔드 변경.
- `.claude/settings.local.json` 수정.
- 모바일 관련 작업.

## 사용자와 정한 것
- 사용자는 로그인 없는 로컬 단일 사용자(`dev_user()`). 에이전트가 user_id를 지정할 수 없다.
- 에이전트는 DB에 직접 접속(psql, docker exec, 임의 SQL)하지 않는다. 조회는 새 조회 명령, 저장은 기존 가져오기 명령만 쓴다.
- 저장은 항상 JSON 만들기 → `--dry-run` → 사용자 허락 → 실제 저장이고 실제 저장은 매번 사용자에게 묻는다. 에이전트는 `--replace-verified`를 쓰지 않는다.
- 공고분석뿐 아니라 자소서·경력기술서도 같은 방식으로 `documents`에 저장한다 (2단계에서 다룬다).
- 에이전트 이름: `job-analyst`, `doc-writer`, `risk-checker`, `doc-reviewer` (`job-agents` 작업).
- 이 작업은 1단계(조회 명령+권한)만 지시서로 한다. 에이전트 파일은 병합 뒤 `job-agents` 작업에서 한다 (사용자 결정, 2026-10-23).
- 권한은 커밋되는 `.claude/settings.json`에 넣는다 (사용자 결정, 2026-10-23).
