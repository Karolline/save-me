# 작업: import-confirm (진짜 DB에 넣는 가져오기는 사람이 터미널에서 확인해야만 진행)

## 목표
Claude 에이전트가 권한 모드(auto, bypass 등)와 상관없이 혼자서는 진짜 DB `saveme`에 가져오기를 할 수 없게 한다. 가져오기 명령 자체가 "사람이 키보드로 입력하는 확인"을 요구한다. (이슈 #6의 안전장치. 에이전트가 쓰는 조회 명령 `agent_read`는 이미 병합됐다. 에이전트 파일 4개는 이 작업 다음 `job-agents`에서 만든다.)

## 배경
- 가져오기 명령(`backend/app/importers/*.py`)은 `--dry-run`을 빼면 `--database-url`이 가리키는 DB에 쓴다. 권한 규칙(`.claude/settings.json`)으로는 "`--dry-run` 없는 저장은 묻는다"를 만들 수 없고(규칙 우선순위 deny > ask > allow 때문에 `ask`를 걸면 `--dry-run` 허용이 덮인다), 사용자가 auto 모드를 쓰면 확인 창도 안 뜬다 (2026-10-23 새 세션에서 시험해 확인).
- 그래서 권한 설정에 기대지 않고 **코드로** 막는다. 에이전트의 명령 실행(Bash 도구)에는 사람이 치는 키 입력이 없다는 점을 이용한다.

## 동작

### 가져오기 6개 전부
`backend/app/importers/`의 쓰기 가져오기 전부에 같은 규칙을 적용한다: `applications`, `reviews`, `jobs`, `experiences`, `resume`, `documents`. 공통 부분은 한 곳(예: `app/importers/confirm.py`)에 두고 각 `main()`이 부른다. `--dry-run`은 이전과 똑같이 동작한다 (아무것도 안 쓰고 확인도 요구하지 않는다).

### 확인을 요구하는 경우
`--dry-run` 없이 쓰기로 돌릴 때, **대상 DB 이름이 `saveme_dev`가 아니고 테스트 DB도 아닌 경우**(= 진짜 DB `saveme` 등)에 확인을 요구한다. 대상 DB 이름은 `--database-url`(없으면 `DATABASE_URL`, 그것도 없으면 기본 `saveme_dev`)에서 `sqlalchemy.make_url(url).database`로 구한다. 판정은 **확인이 필요 없는 이름을 정해 둔 목록**으로 한다(`saveme_dev`와 테스트 DB 이름). 목록에 없는 이름은 모두 확인을 요구한다 (모르는 DB는 막는 쪽). 테스트가 쓰는 DB 이름 규칙은 `docs/testing.md`와 `tests/conftest.py`를 보고 정한다. 사용자가 이 목록에 `saveme_dev`가 아닌 개인 DB를 더 두는 일은 없다.

### 확인 방식 (터미널 입력)
1. 먼저 시험 실행과 같은 방식으로 돌려 요약을 만든다 (바깥 트랜잭션을 열고 끝에 되돌림. 이때 아무것도 남지 않는다). 지금은 `upgrade(url)`(마이그레이션)이 `--dry-run`이 아닐 때 맨 먼저 도는데, 그것도 DB를 바꾸는 일이므로 **확인을 받은 뒤로** 옮긴다.
2. 요약을 보이고 아래를 출력한다 (글자 그대로):
   ```
   진짜 데이터베이스 "<DB 이름>"에 위 내용을 넣습니다.
   계속하려면 DB 이름 <DB 이름> 을(를) 그대로 입력하세요 (그 밖의 입력은 취소):
   ```
3. 사람이 입력한 줄이 DB 이름과 정확히 같을 때만 진행한다. 다르거나 빈 줄이면 `취소했어요. 아무것도 쓰지 않았어요.`를 출력하고 종료 코드 1.
4. **입력을 받을 수 없는 환경이면 묻지 않고 실패한다**: `sys.stdin.isatty()`가 거짓이면(에이전트의 Bash 도구, 파이프, `echo y |` 같은 입력 흉내 모두) 다음을 출력하고 종료 코드 1, 아무것도 쓰지 않는다 (마이그레이션도 하지 않는다):
   ```
   진짜 데이터베이스 "<DB 이름>"에 넣으려면 사람이 터미널에서 직접 확인해야 해요. 이 명령을 직접 열어 둔 터미널(PowerShell)에서 다시 실행해 주세요.
   ```
   이 줄 앞에 요약(시험 실행 결과)을 보여줘도 된다. 사용자가 확인 없이 쓰는 우회로(`--yes`, `--force`, 환경 변수 등)는 **만들지 않는다**. 테스트에서는 확인 함수를 주입하거나 `monkeypatch`로 바꾼다 (명령줄 옵션이나 환경 변수로 건너뛰는 길을 만들지 않는다).
5. 요약에 "에이전트용 조회 명령 `agent_read`" 얘기를 넣지 않는다.

### 알아 둘 점 (개발자가 확인할 것)
- Claude Code의 `!` 접두사 실행이나 VS Code 확장의 터미널이 입력을 받는 진짜 TTY인지는 환경에 따라 다르다. **확인할 수 없으면 사용자에게 "직접 연 PowerShell 창에서 실행하라"고 안내하는 문구를 쓰고, `!`로 된다고 단정하지 않는다.** 실제로 PowerShell 창에서 해 본 결과는 보고서에 적는다 (`saveme_dev`에 대해서가 아니라, 확인 요구를 보려면 DB 이름이 `saveme_dev`가 아니어야 하므로 **임시 PostgreSQL 컨테이너에 `saveme` 이름의 DB를 만들어 그것으로** 시험한다. 진짜 `saveme`(포트 5442)에는 닿지 않는다).

### 스킬과 문서
- `.claude/skills/import-jobs/SKILL.md`: 지금은 Claude가 `--dry-run` 없는 저장을 직접 돌린다. 이제 사람이 해야 하므로 바꾼다: 시험 실행(`--dry-run`)과 백업은 Claude가 하고, 저장 단계에서는 **실행할 명령을 정확히 보여주고** "직접 연 PowerShell 창에서 실행하고 DB 이름을 입력해 주세요, 끝나면 알려 주세요"라고 하고 기다린다. 사용자가 끝났다고 하면 결과를 확인(`agent_read jobs`는 `saveme_dev`가 기본이라 그것으로는 안 되고, 사용자가 붙여 준 출력 요약으로 확인)하고 파일을 `done/`으로 옮긴다. 다른 단계는 그대로.
- `docs/local-operations.md`, `docs/job-inbox.md`, `AGENTS.md`의 "로컬 운영" 절에서 "`saveme`에 넣기"를 말하는 곳에 "진짜 DB에는 사람이 터미널에서 DB 이름을 입력해 확인해야 한다"를 짧게 더한다 (이미 있는 문장을 고치는 정도, 길게 쓰지 않는다).
- `docs/testing.md`에 새 테스트 파일이 있으면 표에 줄을 더한다.

### 권한 규칙 보강 (`.claude/settings.json`)
이 작업은 같은 안전장치의 일부라서 지난 리뷰의 지적을 함께 고친다:
- 허용 규칙의 `*--dry-run*`을 독립된 인자일 때만 맞게 `* --dry-run*`(앞에 공백)으로 좁힌다. Bash와 PowerShell 둘 다. 인자 순서를 바꾼 명령(`--dry-run`이 맨 앞/중간/끝)도 맞는지 `claude -p --permission-mode dontAsk`로 다시 시험한다.
- 거부 규칙에 `docker container exec*`, `docker compose * exec*`(Bash와 PowerShell)를 더한다.
- 위 두 가지의 시험 방법과 결과를 보고서에 적는다. 사용자가 auto 모드를 써서 확인 창은 시험할 수 없다는 점도 적는다.

## 데이터와 API
- 새 테이블·칸·마이그레이션·HTTP 엔드포인트 없음.

## 끝났다고 보는 조건
- 테스트 (단위, PostgreSQL):
  - 대상 DB 이름이 `saveme_dev`/테스트 DB 이름이면 확인을 묻지 않고 그대로 가져온다 (기존 가져오기 테스트가 그대로 통과).
  - 그 밖의 DB 이름(`saveme`)이고 입력이 TTY가 아니면: 종료 코드 1, 안내 문구, **DB에 아무것도 없다** (행 수 전후 같음. 마이그레이션도 안 됨: 새 빈 DB에서 테이블이 안 생김).
  - 그 밖의 DB 이름이고 TTY이며 DB 이름을 바르게 입력하면 가져온다. 틀린 입력·빈 입력이면 취소(종료 코드 1), 아무것도 안 써진다.
  - `--dry-run`은 어느 DB 이름이든 확인 없이 동작한다.
  - 명령줄 옵션/환경 변수로 확인을 건너뛰는 길이 없다 (인자 파서에 `--yes`/`--force`가 없다는 테스트).
  - 6개 가져오기 모두 같은 확인을 거친다 (각각 최소 하나의 비 TTY 테스트).
- 건드린 영역의 테스트만 돌린다. 전체는 CI에서.
- 직접 연 PowerShell 창에서 임시 컨테이너의 `saveme` 이름 DB로 한 시험 결과가 보고서에 있다 (불가능했다면 이유).
- 스킬·문서 수정, `settings.json` 수정과 그 시험 결과가 보고서에 있다.

## 사용자와 정한 것
- 확인은 진짜 DB(`saveme`)에서만 요구한다. `saveme_dev`와 테스트 DB는 확인 없이 넣는다 (사용자 결정, 2026-10-23).
- 확인 방식은 터미널 입력이다 (사용자 결정, 2026-10-23). 확인 코드 파일 방식은 에이전트가 읽을 수 있어 약해서 쓰지 않는다.
- 이 안전장치를 먼저 병합하고, 그 위에서 에이전트 4개를 만든다 (`import-confirm` → `job-agents`).
- 사용자의 권한 모드는 auto라서 권한 규칙만으로는 확인을 보장할 수 없다.
