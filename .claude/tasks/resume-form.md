# 작업: resume-form (지원서류 이력서 화면 개편)

## 목표
지원서류의 이력서 화면에서 PDF 미리보기와 글 편집 칸을 없애고, A4 서류 한 장 위에서 이름·소개·경력·학력·스킬을 칸마다 바로 눌러 입력하게 한다. 입력한 내용은 칸이 나뉜 구조로 저장한다.

## 동작
화면은 `docs/mockup/resume-form.html`(확정 목업)과 같다. 이 작업은 **이력서(type `resume`) 서류 상세만** 바꾼다. 경력기술서·포트폴리오 상세, 묶음 화면, 리뷰 칸은 그대로다.

- 이력서 상세는 위 줄(묶음으로, 서류 전환, 저장 상태, [이 서류 지우기], [PDF로 내려받기])과 오른쪽 리뷰 칸은 지금과 같다. 가운데 PDF 미리보기 칸과 글 편집 칸(textarea, [서식 안내])을 없애고, 그 자리에 A4 서류 한 장(목업의 `.page`)을 둔다.
- 서류 한 장의 칸 (목업과 같은 순서·모양·자리 표시 글):
  - 머리: 이름(자리 표시 "이름"), 전화번호("전화번호"), 이메일("이메일"), 증명사진 칸("증명사진 3×4cm").
  - 소개 글 (자리 표시 "소개 글: 어떤 사람인지, 어떤 일을 해 왔는지 두세 문장으로 적어요."). 줄바꿈 유지.
  - 경력: 회사 여러 개. 회사마다 로고 칸, 회사 이름("회사 이름"), 시작("2021.10")·끝("재직중")·고용형태("정규직")·직무("직무"). 회사 안에 업무 묶음 여러 개: 묶음 제목("묶음 제목 (예: 데이터 품질 관리)")과, 묶음 아래가 (가) 줄(글머리) 목록이거나 (나) 번호 붙은 프로젝트 여러 개(프로젝트 제목 "프로젝트 이름 (기간)" + 줄 목록) 중 하나. 줄의 자리 표시 "한 일, 기준, 결과를 한 줄로".
  - 개인 프로젝트: 제목("프로젝트 이름 (기간, 역할)") + 줄 목록, 여러 개.
  - 학력: 학교 여러 개. 로고 칸, 학교 이름, 시작·끝·상태("졸업")·전공.
  - 스킬: 칩 여러 개 (각 칩 글 "스킬").
- 모든 글 칸은 눌러서 바로 고친다 (contenteditable). 붙여넣기는 글자만 들어간다. 이름·회사 이름·묶음 제목 칸에서 Enter는 줄바꿈 없이 무시한다.
- 줄 칸: Enter = 아래에 새 줄, 빈 줄에서 Backspace = 그 줄 지우고 앞 줄 끝으로. 줄을 다 지우면 빈 줄 하나가 남는다.
- 추가·지우기 버튼은 hover가 아니라 늘 보인다(옅게): [+ 회사 추가], [+ 업무 묶음 추가], [+ 프로젝트형 묶음 추가], [+ 프로젝트 추가], [+ 줄 추가], [+ 프로젝트 추가](개인), [+ 학교 추가], [+ 스킬 추가], 각 항목의 ✕. 프로젝트 번호는 지우거나 더하면 다시 1부터 센다. 새 항목이 생기면 그 첫 칸에 커서가 간다.
- 증명사진·로고: 칸을 누르거나 이미지 파일을 끌어다 놓으면 그 화면에만 보인다. **저장하지 않는다**: 화면을 떠나거나 새로 고치면 사라지고, 매번 직접 넣는다 (사용자 결정. 나중에 저장하는 기능은 기획안 "남은 일" 표에 적혀 있다). 사진·로고가 있는 상태로 인쇄해도 들어간다.
- [이력에서 불러오기] (서류 한 장 위의 도구 줄): 누르면 이력 메뉴(`GET /api/resume`)의 내용을 **복사**해 칸을 채운다. 연결이 아니다: 이후 이력 메뉴를 고쳐도 서류는 바뀌지 않는다. 규칙:
  - 이름·전화번호·이메일 ← `basics.name/phone/email`, 소개 글 ← `basics.summary`.
  - 경력 ← `careers` (이력 화면 순서 그대로). 회사 이름 ← `company`. 시작·끝 ← `startedOn`·`endedOn`을 `2021.10` 모양으로 (끝이 비면 "재직중"). 직무 ← `role`. 고용형태는 비워 둔다. 업무 묶음 하나를 만들어 제목은 비우고 줄 ← `duties`의 줄마다 하나(빈 줄은 건너뜀).
  - 학력 ← `educations`: 학교·전공·상태·시작·끝 (같은 날짜 모양).
  - 스킬 ← `skills`의 `items`를 쉼표로 나눠 칩 하나씩 (분류 이름은 버린다. 같은 이름은 한 번만).
  - 개인 프로젝트는 채우지 않는다 (이력 메뉴에 없다).
  - **칸이 이미 채워져 있으면 덮어쓰지 않는다**: 이름·전화·이메일·소개는 비어 있는 칸만, 경력·학력·스킬은 그 목록이 통째로 비어 있을 때(빈 항목 하나만 있는 것도 빈 것으로 본다)만 채운다. 하나라도 채웠으면 토스트 "이력에서 불러왔어요. 비어 있던 칸만 채웠어요." 아무것도 안 채웠으면 "채울 빈 칸이 없어요." 이력이 모두 비어 있으면 "이력 메뉴가 비어 있어요."
  - 불러오기에 실패하면 토스트 "불러오지 못했어요. 다시 시도해 주세요." (세션이 끝났으면 기존 처리).
- 새 이력서 (묶음에서 서류 추가 [이력서]): **빈 칸으로 시작** (자동으로 이력을 채우지 않는다). 칸 하나씩만 있는 빈 서류가 열린다 (회사·학교·스킬·개인 프로젝트 각 빈 항목 하나, 회사는 빈 묶음과 빈 줄 하나).
- 저장: 입력을 멈추고 0.8초 뒤 자동 저장 (지금 `AUTOSAVE_MS`와 같다), 저장 표시·실패 재시도·화면을 떠날 때 마지막 저장·서류 전환 때 저장 먼저, 모두 지금 화면과 같다.
- 인쇄: [PDF로 내려받기]는 지금처럼 브라우저 인쇄 창(`window.print()`)이고 파일 이름도 지금 규칙(`pdfFileName`)이다. 인쇄에는 서류 한 장만 나오고 편집 도구(✕, [+ 추가], 도구 줄)와 비어 있는 자리 표시 글은 나오지 않는다. 증명사진을 넣지 않았으면 점선 칸도 안 나온다. 서류 한 장 폭은 210mm, 인쇄 여백은 목업의 `@page`와 같다. 인쇄할 때 묶음이 쪽 경계에서 잘리지 않게 (`break-inside: avoid`) 목업 CSS를 따른다. (서버 PDF 코드는 건드리지 않는다.)
- 리뷰 칸의 [○○에서 보기 ↗]·`find`로 열면: 서류 한 장의 칸들 중 그 말을 포함하는 첫 칸을 찾아 스크롤하고 칸 전체를 선택한다. 못 찾으면 지금처럼 토스트 "편집기에서 그 부분을 찾지 못했어요"(글 "편집기" → "서류"로 고친다: "서류에서 그 부분을 찾지 못했어요").
- 서류 상세의 `show-edit/preview/review` 탭 전환(좁은 화면)은 건드리지 않는다. 이력서에서는 미리보기가 없어져 "미리보기" 탭 버튼이 없다 (모바일 확인은 하지 않는다. AGENTS.md "모바일").

### 이미 저장된 이력서
- 지금 저장된 이력서는 글(`body`)뿐이고 칸 구조(`data`)가 없다. 이런 이력서를 열면 **글을 읽어 칸으로 자동 변환해서** 새 화면에 보여준다. 글(`body`)은 DB에서 지우거나 바꾸지 않는다 (원본으로 남는다).
- 변환은 프런트엔드 순수 함수(`src/lib/` 아래, 단위 테스트)가 한다. 열기만 해서는 저장하지 않는다. 사용자가 무엇이든 한 번 고치면 그때 칸 구조를 저장한다 (그 서류는 그때부터 칸 구조가 기준이고, `body`는 그대로 남는다). 변환 규칙은 **최선을 다하는 것**이고, 글 모양이 서류마다 달라서(마크다운 비슷한 글, 이력서 HTML에서 옮긴 줄글 등) 100% 맞지 않을 수 있다:
  - 맨 위 첫 줄(`# 이름` 또는 첫 줄 글) → 이름. 다음에 이메일(`@`)·전화(`0`으로 시작하는 숫자)가 있는 줄이 있으면 그 값들을 뽑아 전화·이메일 칸에 (구분은 ` · `, ` / `, 공백).
  - `## 요약`·`## 소개`가 있거나 이름·연락처 다음 섹션 제목 전에 있는 글 문단들 → 소개 글.
  - `경력` 섹션(`## 경력`, 또는 줄 하나가 "경력"인 제목)에서: 회사 제목(`### 회사 · 팀` 또는 제목 줄) → 회사 이름. 바로 아래 `> 2023.01 – 2025.05 · 정규직` 같은 줄이나 `2021.10 - 재직중 / 정규직 / 직무` 줄에서 시작·끝·고용형태·직무를 뽑는다. 그 아래 `- ` 줄들은 한 묶음(제목 없음)의 줄로, 소제목과 `1. 제목` 줄이 나오면 묶음·프로젝트로 나눈다.
  - `기술 스택`·`스킬` 섹션: 표(`| 분류 | 기술 |`)의 기술 칸을 쉼표로 나눠 칩으로, 목록이면 항목마다 칩으로.
  - `학력` 섹션: 학교로 보이는 줄마다 학교 하나 (나머지는 전공·상태 칸에 가능한 만큼).
  - `개인 프로젝트` 섹션: 제목과 `- ` 줄로 같은 방식.
  - **알아보지 못한 글은 버리지 않는다**: 어느 칸에도 못 넣은 글은 모아서 소개 글 칸 아래쪽에 이어 붙여 둔다 (사용자가 직접 옮기게). 글을 읽는 중 오류가 나도 전체를 소개 글 칸 하나에 넣어서 열린다.
- 변환한 서류도 새로 쓴 서류와 똑같이 보이고 고친다.
- 서류 가져오기 명령(`app.importers.documents`)은 바꾸지 않는다. 가져온 이력서는 글(`body`)로 들어가고, 열 때 위 규칙으로 칸이 된다.

## 데이터와 API
- **새 테이블 없음.** `documents`에 칸(컬럼) 하나를 더한다: `data` (JSON, null 가능, 기본 null). 마이그레이션 하나(`uv run alembic revision --autogenerate`, 이름 규칙·DB 중립 기본값 확인). 기존 줄은 `data` = null이라 그대로 둔다. 이 칸은 이력서(`resume`)에서만 쓴다. 경력기술서·포트폴리오는 계속 `body`만 쓴다.
- JSON 모양 (Pydantic `ResumeData`, camelCase, `app/models.py`. 프런트엔드 타입과 mock도 같이):
  ```
  ResumeData {
    name: str, phone: str, email: str, intro: str,
    careers: [{ company, from, to, type, role,
                blocks: [{ title, items: [str], projects: [{ title, items: [str] }] }] }],
    personalProjects: [{ title, items: [str] }],
    educations: [{ school, from, to, status, major }],
    skills: [str]
  }
  ```
  전부 문자열(날짜도 "2021.10" 같은 글 그대로, 자유 입력). 모두 기본값 빈 값. 한 묶음(block)은 `items`와 `projects` 중 하나만 채운다는 것이 화면의 약속이고, API는 둘 다 받아 그대로 저장한다. 글 길이 제한은 서류 글(`body`)이 쓰는 한도(있으면)와 맞춘다: 없으면 JSON 전체 크기 100KB 이하(넘으면 422).
- 서류 응답(`Document`, `GET /api/document-groups/{id}/documents/{type}`와 만들기·저장 응답)에 `data: ResumeData | null`을 더한다.
- 저장 `PUT /api/document-groups/{id}/documents/{type}`: 지금 요청 `{ "body": "..." }`에 더해 이력서에서는 `{ "data": { ... } }`도 받는다. `data`가 오면 `data`를 저장하고 `body`는 바꾸지 않는다. `body`가 오면 지금처럼 `body`를 저장한다. 둘 다 오면 422. `data`를 `resume`이 아닌 종류에 보내면 422. 가져온 서류(`source` imported)를 `data`로 저장하면 지금 규칙대로 "가져옴 · 내가 수정"(`imported_edited`)이 된다.
- 서류 만들기 `POST .../documents`: 이력서는 `{ "type": "resume", "data": {...} }`(빈 구조)도 받는다. `body`·`data`를 둘 다 안 보내면 지금처럼 빈 글(`body` ""). 이력서를 이 화면에서 만들면 빈 구조 `data`를 보낸다.
- 프런트엔드 서비스(`types.ts` `SaveMeService`, `httpService.ts`, `mockService.ts`): `createDocument`·`saveDocument`가 `data`를 다루고(예: 두 번째 인자를 `{ body } | { data }`로), `SavedDocument`에 `data: ResumeData | null`. mock도 같은 규칙(둘 다 오면 오류, 가져온 서류 출처 바꾸기 포함).
- `app/stores/`의 서류 store 메서드는 이미 `user_id`를 받는다. 새 칸 때문에 바꿀 메서드도 같다.
- 서류를 지우거나 묶음을 지우면 `data`도 같이 지워진다 (같은 줄이라 자동).

## 끝났다고 보는 조건
- 이력서 상세에 PDF 미리보기 칸과 글 편집 칸이 없고, 서류 한 장(칸 입력)이 있다. 경력기술서·포트폴리오 상세는 지금과 똑같이 동작한다 (기존 테스트 통과).
- 칸 입력·줄 Enter/Backspace·추가·지우기·번호 다시 세기·붙여넣기 글자만, [이력에서 불러오기](빈 칸만 채움, 토스트 3종), 사진·로고(저장 안 함), 자동 저장·저장 표시·실패 재시도·떠날 때 저장, `find` 이동, 인쇄에 편집 도구가 안 나옴이 테스트로 확인된다 (프런트엔드 컴포넌트 테스트: `documents.test.tsx` 옆 새 파일).
- 변환 함수의 단위 테스트: 샘플 이력서 글(`sampleDocuments.ts`의 `RESUME`)과 이력서 HTML에서 옮긴 줄글 모양의 지어낸 예시(진짜 데이터 쓰지 않음)와 알아보지 못하는 글(소개 글 아래로 이어 붙음)과 빈 글이 각각 칸으로 바뀐다. 변환 결과를 저장할 때까지 서버로 아무것도 안 간다.
- 백엔드: `data` 저장·읽기, 둘 다 보내면 422, `resume` 아닌 종류에 `data`면 422, 가져온 서류를 `data`로 저장하면 출처가 `imported_edited`, 기존 줄(`data` null)은 읽힌다, **남의 데이터는 404** (남의 묶음의 서류를 `data`로 저장·조회). 마이그레이션 테스트 (`tests/unit/test_migrations.py`, PostgreSQL). 가져오기 테스트(`importers/documents`)는 그대로 통과.
- `docs/` 에 이 화면을 설명하는 곳이 있으면 한국어로 고친다 (서류 상세의 3분할 설명 등 코드 주석 포함: `DocumentScreen.tsx`의 위쪽 설명).
- 개발자: 건드린 영역의 테스트, 프런트엔드 빌드(타입 검사), 린트. 전체 테스트는 CI에서.

## 화면
- 확정 목업: `docs/mockup/resume-form.html`. 똑같이 만든다 (서류 한 장의 모양·CSS는 `toss-resume.html`에서 온 것이라 목업 CSS를 `styles.css`로 옮긴다. 앱의 색 토큰은 서류 바깥, 서류 안쪽 색(`--ink`, `--sub`, `--soft`)은 목업 값 그대로).
- 서류 상세의 위 줄·리뷰 칸은 `frontend/src/components/DocumentScreen.tsx`와 같다. 이 화면의 이력서 부분만 새 컴포넌트(예: `ResumeSheet`)로 빼고, 경력기술서·포트폴리오는 지금 코드를 그대로 쓴다.
- 입력 칸이 모두 16px 이상이라는 규칙은 글 칸(contenteditable)이 서류 글꼴(9.5pt)을 쓰는 이 화면에서는 적용하지 않는다: 이 서류는 A4 모양이고 PC 전용이다 (AGENTS.md "모바일"). 단, 도구 줄의 [이력에서 불러오기] 버튼은 지금 버튼 크기 그대로. 이 예외를 `styles.css` 테스트(`16px 이상 확인`)가 막으면 그 테스트에서 서류 한 장 안의 칸을 제외한다.

## 하지 않을 것
- 증명사진·로고 저장 (나중 일).
- 경력기술서·포트폴리오 화면 변경, 서버 PDF 코드 변경, 가져오기 명령 변경, `body` 삭제·수정, 기존 이력서를 DB에서 `data`로 한꺼번에 바꾸는 마이그레이션 (변환은 열 때 화면에서만).
- 새 테이블, 새 의존성 (필요하면 멈추고 보고한다).
- 이력 메뉴와 이력서 칸을 계속 이어 두기 (복사만).
- 모바일 레이아웃·테스트 (AGENTS.md "모바일").

## 사용자와 정한 것
- 목업은 확정이다(`docs/mockup/resume-form.html`).
- 저장은 새 테이블 없이 `documents`에 JSON 칸을 더해서 (사용자 승인 2026-10-25).
- [이력에서 불러오기]는 복사(연결 아님).
- 사진·로고는 이번에 저장하지 않고 매번 직접 넣는다. 나중 일.
- 이미 저장된 이력서는 글을 칸으로 자동 변환해서 연다 (사용자 선택 2026-10-25). 원문 글은 그대로 남긴다. 변환은 완벽하지 않을 수 있고 알아보지 못한 글은 소개 글 아래에 이어 붙인다.
- 새 이력서는 빈 칸으로 시작, [이력에서 불러오기]는 눌러서 쓴다.
