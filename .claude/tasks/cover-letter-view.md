# 작업: cover-letter-view

이슈 #29. 자소서 화면을 조회와 편집으로 나누고, 문항마다 "어필포인트" 메모 칸을 더한다.

## 목표
자소서를 열면 읽기 화면이 먼저 보이고, [편집]을 눌러야 고칠 수 있다. 문항마다 "이 문항에서 무엇을 어떻게 쓸지" 메모(어필포인트)를 적어 둘 수 있다.

## 동작

### 조회와 편집 나누기
- 자소서 서류를 열면(묶음 화면에서 들어오든, 서류 전환 탭으로 오든) **조회 화면**이 먼저 보인다. 지금처럼 바로 편집 화면이 열리지 않는다.
- 조회 화면은 편집 화면과 같은 틀이다: 위에 뒤로가기 · 서류 전환 탭 · 합계, 왼쪽에 문항 목록(클릭하면 그 문항으로), 오른쪽에 문항마다 카드 하나. 다른 점은 입력 칸이 없고 글이 읽기용으로 보인다는 것이다.
  - 카드: `문항 N` 제목, 문항 글, (어필포인트가 비어 있지 않으면) "어필포인트" 제목과 메모, "답변" 제목과 답변, 글자 수 줄(편집 화면의 `cl-counter`와 막대 `cl-meter` 그대로, 제한 대비 상태색 포함).
  - 답변이 비어 있으면 "아직 답변을 쓰지 않았어요"를 흐리게 보인다. 문항 글이 비어 있으면 "문항을 적지 않았어요".
  - 줄바꿈은 입력한 그대로 보인다 (`white-space: pre-wrap`).
- 조회 화면 위에 [편집] 버튼(기본 버튼)과 [자소서 지우기](지금과 같은 확인 창)가 있다. 저장 상태 표시("자동 저장됨…")는 조회에서는 보이지 않는다.
- [편집]을 누르면 편집 화면으로 바뀐다 (같은 경로, 화면 안 상태로 바꿔도 되고 search 값 `?mode=edit`로 해도 된다. 새로고침해도 모드가 유지되는 쪽, 즉 search를 권한다). 편집 화면 맨 위 저장 표시 옆에 [완료] 버튼이 있다.
- [완료]를 누르면 저장 안 된 것을 먼저 저장하고(`flush`), 성공하면 조회 화면으로 돌아간다. 저장에 실패하면 이동하지 않고 지금처럼 "저장하지 못해서 이동하지 않았어요. 다시 시도해 주세요." 토스트를 보인다.
- 편집 화면의 자동 저장, 화면 떠날 때 저장, 차례 보내기, 빈 문항 처리는 지금 그대로 둔다.
- 서류가 자소서뿐인 새 자소서(문항이 하나도 없는 빈 자소서)는 조회할 것이 없으니 **처음부터 편집 화면**으로 연다 (빈 카드 하나가 보이는 지금 모양). 묶음 화면에서 [자소서 추가]로 막 만든 직후도 여기에 해당한다. 문항이 하나라도 적혀 있으면 조회로 연다.
- 편집에서 모든 문항을 비우고 [완료]하면 빈 목록이 저장되고 조회 화면이 아니라 편집 화면에 그대로 남는다 (조회할 것이 없다).
- 조회 화면의 왼쪽 문항 목록 항목을 누르면 그 문항 카드로 스크롤한다 (편집의 `jumpTo`와 같되 포커스는 없다).

### 어필포인트
- 편집 화면 문항 카드에서 **문항 글 칸 바로 아래, 글자 수 제한 위가 아니라 "답변" 위**에 어필포인트 칸을 둔다. 순서: 문항 → 글자 수 제한 → **어필포인트** → 답변. (사용자 요청: 문항 바로 아래, 답변 위. 글자 수 제한은 문항 설정이라 문항 바로 밑에 그대로 두고 그 다음에 어필포인트가 온다.)
- 라벨 "어필포인트", 칸은 여러 줄(`textarea cl-p`, 답변 칸보다 낮게), placeholder "이 문항에서 무엇을 어필하고 어떻게 쓸지 메모하세요". 글자 수를 세지 않는다.
- 어필포인트는 글자 수 계산(카드의 글자 수, 목록의 숫자, 합계, 막대)에 들어가지 않는다. 서류 인쇄·PDF·미리보기에도 나오지 않는다 (자소서는 원래 인쇄/PDF 대상이 아니므로 새로 막을 코드는 없다. 자소서를 글로 내보내는 곳이 있으면 거기서도 뺀다).
- 문항 카드가 "비어 있다"는 판정(`isBlank`)에 어필포인트도 들어간다: 어필포인트만 적은 문항은 빈 문항이 아니라서 저장된다.
- 조회 화면: 어필포인트가 비어 있으면 그 영역을 그리지 않는다.
- 문항 목록의 글자 수 숫자와 합계는 답변만 센다 (지금 그대로).

## 데이터와 API
- `cover_letter_items`에 칸 하나 추가: `appeal` (`Text`, 기본값 빈 글, `server_default=""`, NOT NULL). 마이그레이션 하나 (`uv run alembic revision --autogenerate`, 만든 파일을 읽고 확인. 기존 행은 빈 글이 된다). 기존 진짜 데이터는 `saveme`에 있으니 `saveme_dev`에 먼저 적용해 본다. `tests/unit/test_migrations.py`도 PostgreSQL에서 돌린다.
- `backend/app/models.py`의 `CoverLetterItem`에 `appeal: str = ""` (JSON 이름 `appeal`). 길이 제한은 `answer`와 같은 기준을 따른다. `stores/documents.py`의 `to_cover_letter`와 `save_cover_letter`에서 읽고 쓴다.
- `agent_read.py`가 자소서 문항을 출력하는 곳에 어필포인트를 더한다: 문항·답변 옆에 "어필포인트" 줄. 비어 있으면 줄을 내지 않는다. 이 메모는 사용자의 작성 의도이므로 근거 자료(`--include-reference`가 필요한 것)가 아니다. 다만 면접관 시점 읽기 등 경험을 숨기는 출력이 따로 있다면 거기엔 넣지 않는다 (코드에서 확인하고 보고서에 적는다).
- 프런트엔드: `types.ts`의 `CoverLetterItem`에 `appeal: string`, `emptyItem()`(`lib/coverLetter.ts`), `mockService.ts`, `httpService.ts`(있으면)를 맞춘다.
- 엔드포인트는 그대로(`GET/PUT /api/documents/{group_id}/cover-letter`)이고 본문에 `appeal`이 더해진다. 옛 클라이언트가 `appeal`을 안 보내도 빈 글로 받는다.

## 끝났다고 보는 조건
- 백엔드: 어필포인트가 저장·조회되고 빈 문항 판정과 순서가 유지된다 (`tests/unit/test_cover_letter_store.py`, `tests/integration/test_cover_letter_api.py`에 더한다). `appeal`을 빼고 보내도 저장된다. 남의 자소서에 쓰기·읽기는 404 (이미 있는 테스트가 새 칸으로도 돌면 충분). 마이그레이션 테스트 통과, `saveme_dev`에서 위로·아래로 마이그레이션.
- `agent_read` 단위 테스트: 어필포인트가 있는 문항은 나오고 없으면 줄이 없다.
- 프런트엔드(`CoverLetterScreen.test.tsx` 등):
  - 문항이 있는 자소서를 열면 조회 화면이다 (입력 칸 없음, [편집] 버튼 있음).
  - [편집] → 편집 화면, [완료] → 저장 후 조회 화면. 저장 실패면 이동하지 않고 토스트.
  - 빈 자소서(문항 없음)는 편집 화면으로 열린다.
  - 어필포인트 입력이 저장 요청에 담긴다. 글자 수·합계는 어필포인트에 변하지 않는다. 어필포인트만 적힌 문항은 저장된다.
  - 조회 화면은 어필포인트가 비면 그 영역을 그리지 않고, 있으면 그린다.
  - 서비스 mock과 http 서비스가 `appeal`을 주고받는다 (`coverLetterService.test.ts`).
- `npm run build`(타입 검사), `npm run lint` 통과. 입력 칸 16px 이상 규칙 테스트 통과(새 textarea 포함).
- 전체 테스트는 돌리지 않는다 (AGENTS.md): 건드린 영역만.

## 화면
- 목업은 없다. 편집 화면은 `CoverLetterScreen.tsx`와 `.claude/tasks/cover-letter.mockup.html`(있었다면 이미 지워졌을 수 있다)의 모양을 따르고, 조회 화면은 같은 `cl-wrap`/`cl-toc`/`cl-qs` 구조와 `styles.css`의 기존 `cl-*` 클래스를 재사용해 편집 카드에서 입력 칸만 읽기용 글로 바꾼 모양으로 만든다. 새 CSS는 최소한 (읽기용 글 `.cl-read`, 어필포인트 영역). 색은 기존 토큰만 쓴다.
- 어필포인트 영역은 조회·편집 모두 답변과 구분되게 연한 배경(`var(--surface-2)` 등 기존 토큰)으로 한다.

## 하지 않을 것
- 모바일 레이아웃·테스트 (AGENTS.md).
- 수동 저장으로 바꾸기 (이슈 #19). 자동 저장은 그대로.
- 어필포인트 글자 수 세기, 길이 제한 UI.
- 서버 PDF·인쇄에 어필포인트를 넣기.
- 문항 저장 구조(#22)의 다른 변경, 가져오기 코드 변경 (이미 있는 가져오기는 `appeal`을 비워 두면 된다. 자소서 가져오기가 있으면 안 깨지는지만 확인).
- 이력서/경력기술서/포트폴리오 화면은 건드리지 않는다.

## 사용자와 정한 것
- 조회 화면은 문항 + 어필포인트(있을 때만) + 답변을 보인다.
- 편집을 마치는 방법은 [완료] 버튼 (자동 저장은 유지, 누르면 저장 후 조회로).
- 어필포인트 칸은 편집 카드에서 문항 아래, 답변 위.
- 어필포인트는 글자 수·인쇄·PDF에서 제외 (이슈 #29).
- 빈 자소서는 조회할 것이 없어 편집으로 연다 (기획자 판단, 사용자가 OK 하면 확정).
