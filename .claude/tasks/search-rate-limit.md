# 작업: search-rate-limit (의미 검색 무료 한도 대응, 이슈 #30 후속)

## 목표
Voyage AI 무료 계정(결제 수단 없음)의 속도 제한(분당 요청 3회, 분당 토큰 1만 정도)에서도 `agent_read search`와 `app.search_eval`의 첫 임베딩이 끝나게 한다. 지금은 첫 묶음(64조각)이 토큰 한도를 넘어 바로 `429 Too Many Requests`로 끝나고, 캐시는 전부 끝나야 저장해서 아무것도 남지 않는다.

## 동작
- **토큰 기준 묶음:** 조각을 개수가 아니라 추정 토큰으로 묶는다. 추정은 토크나이저 없이 글자 수를 그대로 토큰 수로 본다 (한국어에서 넉넉한 쪽). 한 묶음의 추정 합이 `BATCH_TOKENS`(모듈 상수, 기본 8000)를 넘지 않게, 개수도 지금처럼 `BATCH_SIZE`(64) 이하로 묶는다. 조각 하나가 8000을 넘으면 그 조각만 혼자 한 묶음.
- **429 다시 시도:** 응답이 429면 기다렸다 같은 묶음을 다시 보낸다. 기다리는 시간은 `Retry-After` 헤더(초)가 있으면 그 값, 없으면 21초 (분당 3회 기준). 같은 묶음에 최대 6번 다시 시도. 기다리기 전에 stderr에 한 줄:
  `속도 제한에 걸려 21초 기다립니다 (다시 시도 1/6)`
  6번 다 실패하면 지금처럼 한 줄 오류와 종료 코드 1:
  `임베딩 API 오류: 429 Too Many Requests. 지금까지 만든 것은 저장했으니 잠시 뒤 다시 돌리면 이어서 합니다.`
- **500대 오류와 네트워크 오류**는 지금처럼 바로 실패 (다시 시도하지 않는다). 401 등 다른 4xx도 지금처럼.
- **묶음 사이 간격:** 다시 시도와 별개로 미리 쉬지는 않는다 (결제한 계정에서 느려지지 않게). 429가 오면 그때 기다린다.
- **진행 표시:** 임베딩할 조각이 있으면 시작 때 stderr에 `임베딩할 조각 N개 (묶음 M개)`, 묶음 하나가 끝날 때마다 `임베딩 중: 3/12 묶음`. 임베딩할 것이 없으면(모두 캐시) 아무것도 찍지 않는다. stdout의 마크다운 결과는 지금과 같다.
- **묶음마다 캐시 저장:** 묶음 하나의 벡터를 받을 때마다 캐시 파일을 다시 쓴다 (지금처럼 임시 파일 → `os.replace`). 저장 내용은 "지금 사용자의 지금 조각 중 벡터가 있는 것"(캐시 적중 + 지금까지 새로 받은 것)이다. 중간에 실패하거나 사용자가 끊어도(Ctrl+C, 에이전트 시간 초과) 이미 받은 묶음은 남아서, 다시 돌리면 남은 조각만 임베딩한다. 지운 경험·섹션 항목을 빼는 규칙은 그대로.
- **질문 임베딩**(`input_type: "query"`)도 같은 429 다시 시도를 쓴다.
- `app.search_eval`은 질문마다 search를 부르므로 같은 길을 탄다. 질문이 많으면 질문 임베딩마다 429가 날 수 있다: 기다렸다 이어 가면 된다 (따로 처리하지 않는다).

## 데이터와 API
- 없음 (DB, 마이그레이션, 엔드포인트, 프런트엔드 변경 없음). 새 의존성 없음 (`time.sleep`, 표준 라이브러리만).
- 테스트에서 바꿔 끼울 수 있게: 실제 HTTP 한 번을 보내는 함수(예: `post_batch(texts, input_type) -> list[list[float]]`)와 기다리는 함수(`sleep`, 모듈 수준)를 분리한다. `embed`를 통째로 가짜로 바꾸는 기존 테스트 방식이 계속 되게 하되, 묶음별 저장은 `embed`보다 아래 층(묶음 단위)을 불러야 하므로 구조는 개발자가 정한다. 기존 테스트가 깨지면 새 구조에 맞춰 고친다.

## 끝났다고 보는 조건
- 테스트 (실제 API 없음, `sleep`은 가짜로 바꿔 실제로 기다리지 않음):
  - 토큰 기준 묶음: 글자 수 합이 `BATCH_TOKENS`를 넘지 않음, 개수 64 이하, 긴 조각 하나는 혼자.
  - 429 뒤 성공: 기다린 시간(`Retry-After` 있을 때 그 값, 없을 때 21), stderr 메시지, 결과가 맞음.
  - 429가 7번(처음 + 다시 시도 6번) 계속되면 위 오류 메시지와 종료 코드 1.
  - 401과 500은 다시 시도하지 않음.
  - 묶음별 저장: 둘째 묶음에서 실패하면 캐시에 첫 묶음 조각만 남고, 다시 돌리면 남은 조각만 임베딩함.
  - 진행 표시 문구, 모두 캐시면 진행 표시 없음.
  - 기존 의미 검색 테스트(다른 사용자 분리 등)가 계속 통과.
- `docs/semantic-search.md`에 "무료 계정의 속도 제한" 절: 결제 수단 없는 계정의 한도, 첫 실행이 몇 분 걸릴 수 있고 끊겨도 다시 돌리면 이어서 한다는 것, 에이전트가 첫 실행을 할 때는 명령 시간 제한을 길게(예: 10분) 주거나 사용자가 터미널에서 한 번 돌려 두면 된다는 것.
- 백엔드 해당 테스트 통과 (전체는 CI).

## 화면
- 없음 (명령줄 출력만).

## 하지 않을 것
- 결제 계정용 미리 쉬기(throttle), 새 명령·옵션(`--warm` 등), 토크나이저 의존성.
- 지난 리뷰의 다른 지적(AGENTS.md 문장, 남의 경험 ID 평가 테스트, 고르기 파일 형식 오류): 이번엔 하지 않는다.
- 실제 API 호출 테스트, 버전 올리기.

## 사용자와 정한 것
- 결제(5달러 충전) 대신 코드를 고쳐 무료 한도에서 돌게 한다.
- 첫 실행이 길어도 따로 미리 만들기 명령을 두지 않고, 묶음마다 저장해서 끊겨도 다시 돌리면 이어 가게 한다.
- 범위는 한도 대응만.
