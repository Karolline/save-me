# 테스트

## 백엔드 (`backend/tests/`)

`backend/` 안에서 돌린다:

```
uv run pytest                     # 전부
uv run pytest tests/unit          # 단위 테스트만
uv run pytest tests/integration   # 통합 테스트만
```

PDF 테스트(`test_documents_pdf.py`)는 헤드리스 Chromium과 프런트엔드 빌드가 있어야 돈다. 한 번만: `backend/`에서 `uv run playwright install chromium`, `frontend/`에서 `npm run build`. 없으면 건너뛰고 까닭을 보인다 (`-rs`).

공통 fixture는 `tests/conftest.py`에 있다. 앱을 import하기 전에 `DATABASE_URL`을 `TEST_DATABASE_URL`로 정하고, 진짜 DB(`saveme`, `saveme_dev`)를 가리키면 거부해서 어떤 테스트도 진짜 DB를 건드리지 않는다. `client`와 `other_client`는 서로 다른 두 사용자로 로그인해 CSRF 헤더를 보내고, `anon_client`는 세션이 없다. 가짜 시계가 시각을 정해 준다 (2026-09-01부터). `application(...)`은 `ApplicationInput`을 만든다.

### PostgreSQL 준비

백엔드 테스트는 PostgreSQL에서만 돈다 (SQLite는 쓰지 않는다, 사용자 결정 2026-10-22). `TEST_DATABASE_URL`에 `saveme`나 `saveme_dev`가 아닌 버려도 되는 DB를 준다. 안 주면 아래 임시 컨테이너 주소(`127.0.0.1:55442/test`)를 쓰므로, 그 컨테이너가 떠 있어야 한다. 테스트는 그 DB 안에 `saveme_test_*` 스키마를 만들고 지우며, 테스트마다 모든 테이블을 비운다. Docker에서는 `localhost`가 아니라 `127.0.0.1`을 쓴다 (Windows에서 `localhost`는 IPv6를 먼저 시도해 멈출 수 있다).

```
docker run -d --rm --name saveme-testpg -e POSTGRES_PASSWORD=test -e POSTGRES_DB=test -p 127.0.0.1:55442:5432 postgres:18-alpine
docker exec saveme-testpg pg_isready -U postgres -d test   # "accepting connections"가 나올 때까지 반복
TEST_DATABASE_URL=postgresql://postgres:test@127.0.0.1:55442/test uv run pytest
docker stop saveme-testpg   # --rm이라 지워진다
```

데몬이 안 돌아서 `docker info`가 실패하면 Docker Desktop을 먼저 켠다 (이 PC: `C:\Users\hyejin\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`, PowerShell의 `Start-Process` 등) 그리고 `docker info`가 될 때까지 기다린다. Docker Desktop은 켜 둔 채로 두고, 내가 띄운 컨테이너만 멈춘다.

### docker-compose.yaml로

`tests/compose/test_compose.py`는 진짜 스택을 빌드해 띄우고 (`docker compose up --build`), 프런트엔드가 이미지에 빌드돼 제공되는지, DB 두 개가 있는지, 이미지 안의 Chromium이 한글 글꼴로 서류 PDF를 만드는지, 앱이 `saveme`에 지원 건을 저장하는지 (`psql`로 읽어 봄) 확인한다. Docker가 필요하고 처음 빌드는 Chromium을 받느라 몇 분 걸리며, 기본 실행에는 들어 있지 않다:

```
uv run pytest tests/compose
```

자기 프로젝트 이름(`saveme-test`), 볼륨, 포트(앱 18100, PostgreSQL 15442)를 써서 진짜 데이터가 든 스택은 그대로 돈다. 테스트 볼륨은 끝나면 지운다. 빌드가 `saveme` 이미지의 태그는 다시 붙인다.
