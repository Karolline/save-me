# 경험 의미 검색 (이슈 #30)

에이전트가 경험 카드를 태그가 아니라 뜻으로 찾게 하는 도구와, 지금 방식(목록 보고 고르기)과 정답률을 비교하는 평가 스크립트.

## 무엇을 하나

```
cd backend
uv run python -m app.agent_read search "<질문>" [--k N]
```

- 경험을 섹션 조각으로 나눈다: 요약(이름, 프로젝트, 요약), 상황(상황, 담당 범위), 과제, 행동(행동 소개, 행동 항목의 제목과 세부 내용), 결과(수치, 내가 한 것의 결과, 팀의 결과). 빈 섹션은 만들지 않고, 근거가 아닌 칸(예상 질문과 답, 프레이밍, 어필 등)은 넣지 않는다. 조각 글 앞에 `[경험 이름]`을 붙인다.
- 질문과 조각의 코사인 유사도를 Python에서 계산하고, 경험별로 가장 높은 조각 점수로 정렬해 위 N개(기본 5)를 보인다. 경험마다 머리말(`experience-index`와 같은 모양, 사람 확인 '미확인' 표시 포함), 점수, 가장 가까운 섹션, 그 조각 글(300자에서 자름)을 보이고, 본문은 `experience <ID>`로 읽게 안내한다.
- 조회 DB 고르는 규칙과 맨 위 `조회 DB:` 줄은 다른 `agent_read` 명령과 같다. DB에는 쓰지 않는다.

## 키 넣는 법

Voyage AI의 API 키가 필요하다. `backend/.env`(git이 무시한다)에 한 줄을 적거나 환경 변수로 둔다.

```
VOYAGE_API_KEY=<키>
```

`backend/.env.example`에 양식이 있다. 환경 변수가 먼저고, 없으면 `.env`의 줄을 읽는다 (search와 평가 스크립트만 이 파일을 읽는다). 모델은 환경 변수 `VOYAGE_MODEL`, 없으면 `voyage-3.5`. 키가 없으면 안내 메시지와 함께 종료 코드 2, API 오류(네트워크, 401, 429 등)는 `임베딩 API 오류: ...` 한 줄과 종료 코드 1.

## 밖으로 나가는 것

**경험 원문(조각 글)과 질문이 Voyage AI로 전송된다.** 진짜 데이터가 든 DB(`saveme`)를 조회하면 진짜 경험 글이 나간다. 쓰기 전에 Voyage AI의 데이터 사용 약관을 확인하고, 내보내고 싶지 않은 글이 있으면 쓰지 않는다. 새 의존성은 없고 표준 라이브러리 `urllib`로 REST 호출을 한다.

## 캐시

벡터는 DB가 아니라 저장소 맨 위 `private/embeddings/<DB 이름>.json`에 둔다 (git이 무시한다). 항목 키는 (사용자, 경험 ID, 섹션), 값은 내용 해시(조각 글과 모델 이름의 sha256)와 벡터다.

- search를 돌 때 해시가 없거나 다른 조각만 다시 임베딩한다. 카드를 고치면 그 카드의 바뀐 조각만, 모델을 바꾸면 모두 다시 한다.
- 지금 DB에 없는 경험·섹션의 항목은 지우고 파일을 다시 쓴다 (임시 파일에 쓰고 바꾼다).
- 파일이 깨졌으면 무시하고 새로 만든다. 지워도 안전하다 (다음에 다시 임베딩한다).

## 평가 방법

지금 방식과 search 중 어느 쪽이 정답 경험을 더 잘 찾는지 잰다.

1. 질문 파일을 `private/search-eval/`에 만든다 (개인 글은 `private/`에만, 커밋하지 않는다):

   ```json
   {"questions": [{"id": "q1", "question": "...", "answers": [12, 34]}]}
   ```

   `answers`는 그 질문에 맞는 경험 ID들이다.
2. (지금 방식) 에이전트가 `experience-index`만 보고 질문마다 고른 경험 ID를 위에서부터 적은 고르기 파일을 만든다:

   ```json
   {"picks": {"q1": [12, 7, 3]}}
   ```

3. 실행한다:

   ```
   cd backend
   uv run python -m app.search_eval ../private/search-eval/questions.json --picks ../private/search-eval/picks.json --k 5
   ```

   질문마다 search 결과 위 k개와 고르기 위 k개로 recall@k(정답 중 맞힌 비율)와 hit@k(하나라도 맞혔나)를 구하고 평균을 낸다. k와 k보다 작은 1, 3, 5도 함께 낸다. 고르기 파일에 없는 질문은 고른 게 없는 것으로 센다.
4. 화면에는 개인 글 없이 숫자 요약 표만 찍힌다 (그대로 이 문서에 붙일 수 있다). 질문 글, 정답, 두 방식의 결과는 `private/search-eval/result-<YYYYMMDD-HHMM>.md`에 쓴다.
5. 정답이나 고르기에 있는 ID가 그 사용자의 경험이 아니면 경고를 한 줄 찍고 그 ID는 계산에서 뺀다. 쓸 수 있는 정답이 없는 질문은 건너뛴다.
