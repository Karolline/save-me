# SaveMe 화면 명세 1차 — 최초 화면 (가짜 데이터)

작성: 2026-10-13. 처음엔 외부 화면 생성 도구에 넣을 프롬프트로 썼지만, 2026-10-14부터 그 도구는 쓰지 않는다. 지금은 목업 페이지를 만들 때 따르는 **화면 명세**다.
가짜 데이터의 회사명·사람·경험은 모두 지어낸 것이다. 실제 지원 기록을 넣지 않았다.

> 이 파일은 `tech 기획안.md`의 "S1"이다. 이후 기술 결정으로 바뀐 점(로그인·가입 화면, 지원 건 추가·수정 폼 등)은 `tech 기획안.md` 4.2의 추가 화면 명세(S2)에 있다. 아래의 `src/data/mock.ts`·Supabase 문장은 무시하고, 데이터 접근은 `tech 기획안.md` 5.4를 따른다.

---

취업 준비생이 자기 지원 현황, 채용공고 분석, 경력 경험, 프로필을 한곳에서 관리하는 웹앱 "SaveMe"의 첫 화면 버전을 만들어 줘.
이번엔 **화면만** 만든다. 로그인·DB·AI 연동은 하지 않는다. 모든 데이터는 가짜 데이터로 채운다.

## 공통

- UI 언어는 한국어.
- **PC가 주 사용 환경**이고 모바일에서도 깨지지 않아야 한다.
  - PC(1024px 이상): 왼쪽 고정 사이드바 메뉴 + 오른쪽 본문 (본문 최대 너비 약 1120px)
  - 모바일: 사이드바 대신 하단 탭 바 (아이콘 + 짧은 라벨)
- 메뉴는 4개, 이 순서로 둔다: **지원현황 · 공고분석 · 경험 · 프로필**
- **첫 진입(`/`) 화면은 지원현황**이다. `/` 에서 `/applications`로 보내거나 `/`가 지원현황을 그대로 보여준다.
- 라우트: `/applications`, `/applications/:id`, `/jobs`, `/jobs/:id`, `/experiences`, `/experiences/:id`, `/profile`
- 라이트/다크 모드 둘 다 지원 (시스템 설정 따름 + 사이드바 하단에 전환 버튼).
- 톤: 차분한 업무용 도구. 흰 카드, 얇은 회색 테두리, 둥근 모서리 약 10px, 강조색은 남색 계열 하나. 장식·그라데이션·이모지 없이.
- 긴 글(면접 후기, 공고 분석 결과, 경험 본문)은 **마크다운 문자열**로 저장되어 있다고 가정하고 마크다운 렌더러로 보여준다 (react-markdown 등).
- 가짜 데이터는 전부 `src/data/mock.ts` 한 파일에 TypeScript 타입과 함께 모아 둔다. 나중에 Supabase로 바꿀 때 이 파일만 교체할 수 있게, 화면 컴포넌트는 데이터를 직접 만들지 말고 이 파일에서 가져온다.
- 화면 오른쪽 아래에 **"AI에게 말로 등록하기"** 떠 있는 버튼을 하나 둔다. 누르면 오른쪽에서 채팅 패널이 열리고, 가짜 대화 예시 2~3턴과 "이렇게 등록할까요? [등록] [취소]" 확인 카드 하나를 보여준다. 실제 동작은 없다 (UI 자리만).

## 1. 지원현황 (`/applications`) — 가장 중요한 화면

회사별 지원 건을 **한 줄씩 가로 막대로 보여주는 타임라인 차트**다. 차트 라이브러리 없이 CSS grid + 절대 위치로 그려도 된다.

### 상단
- 제목: "지원 현황 · 2025.11 – 2026.10" (표시 기간은 데이터에서 계산)
- 한 줄 설명: "막대는 지원부터 마지막 전형까지의 기간, 막대 색은 도달한 단계, 오른쪽 문구는 진행 순서와 결과입니다."
- **통계 줄**: `전체 20 · 진행 중 2 · 서류 탈락 11 · 코테 단계 탈락 2 · 면접 탈락 3 · 공고 마감 1 · 무응답 2` 처럼 숫자(고정폭 글꼴, 굵게) + 라벨을 가로로 나열. 숫자는 데이터에서 계산.
- **범례**:
  - 막대 색 4단계(같은 파랑 계열, 진할수록 더 멀리 감): 서류 / 서류 합격·코테·과제 / 1차 면접 / 2차 면접 이상
  - 결과 기호: `✕ 탈락`(빨강) · `◇ 합격 후 공고 마감`(황토) · `… 무응답`(회색) · `▶ 진행 중`(초록)
- **필터 버튼**(토글 그룹): 전체 / 진행 중 / 종료

### 차트
- 카드 안에 그린다. 왼쪽 150px은 회사명 칸, 오른쪽은 월 축.
- **x축**: 월 단위 12칸. 각 칸 가운데에 `MM`, 첫 칸과 1월에는 위에 연도도 표시. 세로 격자선을 연하게.
- **행**: 지원 건 하나당 한 줄(높이 약 38px), 지원 시작 시점이 이른 순으로 정렬.
  - 회사명 아래에 작은 회색 글씨로 부가 정보(예: "상반기", "7월 제출")가 있을 수 있다. 같은 회사에 두 번 지원한 경우다.
  - **막대**: 시작 = 첫 전형 시점, 끝 = 마지막 전형 시점(또는 별도의 결과 통보 시점). 최소 너비를 둬서 하루짜리도 보이게. 색 = 도달 단계(depth 1~4).
  - **점**: 두 번째 전형부터 각 전형 시점에 막대와 같은 색의 작은 원.
  - **오른쪽 문구**: `서류 → 1차 면접 → 2차 면접 → ✕ 2차 면접 탈락` 처럼 단계를 화살표로 잇고 결과 기호와 결과 문구를 붙인다. 막대가 차트 앞쪽 60% 안에 있으면 막대 오른쪽에, 뒤쪽에 있으면 막대 왼쪽에 문구를 둬서 잘리지 않게.
- 행에 마우스를 올리면 행 배경이 옅게 바뀌고 **툴팁**: 회사명 · 시기(예: "2026-07 ~ 08") / 단계 연결 / 결과.
- 필터를 "진행 중"으로 바꾸면 해당 행만 남기고, x축 시작을 남은 행의 가장 이른 달로 당겨서 다시 그린다.
- 카드 아래 접히는 **"표로 보기"**: 열 = 시기 · 기업 · 진행 단계 · 결과.
- **모바일**: 차트 카드는 가로 스크롤(차트 최소 너비 약 860px)로 두고, 그 위에 "옆으로 밀어서 보기" 안내. 각 행 아래에 단계 연결 문구를 한 줄로 따로 보여줘도 좋다.

### 지원 건 상세
회사명을 누르면 PC에서는 오른쪽에서 슬라이드 패널, 모바일에서는 전체 화면으로 `/applications/:id`를 연다. 섹션:
1. **공고** — 공고 제목, 원문 링크, 연결된 공고분석이 있으면 그 페이지로 가는 링크
2. **전형 단계별 자료** — 단계(서류/코테/1차 면접…)별로 묶은 제출 파일 목록. 파일명 + 확장자 배지(pdf, docx, md). 누르면 미리보기 모달(가짜 텍스트).
3. **면접 후기** — 후기 목록. 하나를 열면 마크다운으로 렌더링한다. 후기는 이런 구조의 마크다운이다:
   ```
   ## Q. 가장 어려웠던 장애 대응 경험은?
   ### 내 답
   ...
   ### 다시 답한다면
   ...
   ### AI 첨언
   ...
   ```
   `### 내 답`, `### 다시 답한다면`, `### AI 첨언` 블록은 배경색을 서로 다르게(연한 파랑 / 연한 초록 / 연한 노랑) 칠해 구분하고, AI 첨언 블록에는 "AI가 쓴 글 · 경험 근거 아님" 작은 라벨을 붙인다. 위쪽에 "읽기 / 편집" 토글 — 편집은 왼쪽 textarea + 오른쪽 미리보기 (저장은 가짜).
4. **느낀점** — textarea + 저장 버튼 (가짜 저장, 토스트만 띄움)

## 2. 공고분석 (`/jobs`)

- 분석한 채용공고 목록. 최근 분석일이 위.
- 필터 토글: **미정 / 지원 / 미지원 / 전체**, 버튼마다 개수 표시. **처음엔 "미정"이 선택된 상태**.
- 각 행: 분석일(고정폭 글꼴) · 회사 · 직무 한 줄 · 지원여부 배지 · 적합도(상/중/하 배지).
- 상단 오른쪽 "공고 추가" 버튼 → 회사명·URL·공고 원문 붙여넣기 칸이 있는 모달 (저장은 가짜).
- 행을 누르면 `/jobs/:id`: 공고 요약, **요구 역량 ↔ 매칭된 내 경험** 표(요구 역량 / 매칭 경험 링크 / 근거 강도 상·중·하·없음), "경험 DB에 근거가 없는 요구 역량" 경고 박스, 마크다운으로 된 분석 본문. 지원여부를 바꾸는 드롭다운.

## 3. 경험 (`/experiences`)

- 경험 카드 목록(PC 2열 그리드, 모바일 1열). 카드: 기간 · 프로젝트명 · 한 줄 요약 · 태그 칩 몇 개 · 소속/역할.
- 상단에 검색창 + 태그 칩 필터(여러 개 선택).
- 각 카드 오른쪽 위에 **확인 상태 배지**: "확인됨"(초록) 또는 "미확인"(노랑). 미확인은 AI가 만들거나 고친 뒤 본인이 아직 안 읽은 것이라는 뜻. 목록 위에 "미확인만 보기" 토글.
- `/experiences/:id` 상세: 상단 메타(기간·소속·역할·태그·확인 상태), 그다음 섹션 순서대로
  `한 줄 요약 / 상황 (Situation) / 과제 (Task) / 행동 (Action) / 결과 (Result) / 어필 포인트 / 프레이밍 주의 / 예상 질문과 답변`.
  - 상황~결과는 마크다운 렌더링.
  - **프레이밍 주의**는 주황 테두리의 주의 박스.
  - **예상 질문과 답변**은 기본으로 접혀 있고, 제목 옆에 "면접 대비용 예시 · 서류 근거로 쓰지 않음" 회색 라벨.
- 오른쪽 위 "편집" 버튼 → 섹션별 마크다운 편집 (가짜 저장).

## 4. 프로필 (`/profile`) → 2026-10-14 메뉴 이름을 **이력**(`/resume`)으로 바꿈

한 페이지에 카드 여러 개:
- 기본 정보(이름, 연락처, 현재 상태), 경력(회사·기간·역할 타임라인 목록), 학력, 자격증
- 희망 직무, 기술 스택(카테고리별 칩), 커리어 방향(마크다운)
- 인성 답변: 질문 → 실제로 한 답 → 교훈, 아코디언으로
- 각 카드에 편집 버튼 (가짜)

## 가짜 데이터 (전부 지어낸 것으로)

- 사용자: "김지원", 데이터 엔지니어 경력 5년, 가상의 회사 2곳 경력.
- 회사명은 실제 기업명을 쓰지 말고 지어낸 이름을 쓴다 (예: 한빛증권, 누리커머스, 별빛게임즈, 온새미로보험, 파랑모빌리티, 다솜페이…).
- **지원 건 20개**, 기간 2025-11 ~ 2026-10. 분포를 대략 이렇게:
  - 서류 탈락 11개 (서류 단계만, 일부는 결과 통보까지 1개월 이상 걸려 막대가 길다)
  - 코딩테스트 단계 탈락 2개
  - 1차 면접 탈락 2개, 2차 면접 탈락 1개
  - 서류 합격 후 공고 마감 1개, 무응답 2개(그중 1개는 3차 면접까지 간 뒤 무응답)

  - 2026-07~08에 지원이 몰려 있게
- 각 지원 건 데이터 모양 예:
  ```ts
  { id, company, sub?: "하반기", stages: [{ name: "서류", at: "2026-07-12" }, { name: "1차 면접", at: "2026-08-14" }],
    endAt?: "2026-08-30", result: "fail" | "open" | "none" | "ing", resultText: "1차 면접 탈락",
    depth: 1 | 2 | 3 | 4, period: "2026-07 ~ 08", jobId?, files: [...], reviews: [...], note: "" }
  ```
- 면접까지 간 지원 건 3~4개에는 면접 후기(질문 4~6개, 위 마크다운 구조)와 제출 파일 3~5개를 넣는다.
